# OmniCrawler 任务创建体验重构 PRD（任务画布 Task Canvas）

> **当前实现说明（2026-09）**：用户界面已统一命名为“任务工作台”。首页使用单一“网址或描述”入口并展示真实最近任务；侧栏按工作、自动化、工具和高级分组；试跑状态与运行按钮位于滚动区外的常驻操作栏。试跑失效按配置依赖判断：网址、范围、抓取参数和字段变化需要重试跑，输出与调度采用独立本地验证。首次引导也已升级为工作台内可跳过的检查清单。下文保留早期“任务画布”术语，用于记录设计演进。

> 状态：草案 · 版本：0.1 · 日期：2026-08-13
> 本文档替代"五步向导"作为 GUI 创建任务的统一体验，并整合首页、模板/场景、B-2 推荐、视觉选择器、智能提取、试跑与运行的全部现有能力。

---

## 1. 背景与原则

### 1.1 现状问题

- 配置任务被拆成"五步向导"，但用户的心智模型是"**我要什么数据**"，不是"我按什么顺序填表"。
- 能力分散：首页（一句话/快捷任务）、五步向导、模板/场景面板、视觉选择器、B-2 推荐闸门、YAML 编辑器各为独立入口，未形成一条连续路径。
- 智能能力（自然语言、模板推荐、智能提取）是"旁路增强"，没有成为"创建流程"本身。

### 1.2 设计原则

1. **三阶递进法则（70/20/10）**
   - 第一阶（70% 精力）：符合本能，无需指引——改交互，不加指引。
   - 第二阶（20% 精力）：操作伴随反馈——操作前占位/禁用+原因，操作中进度/骨架/防抖，操作后 Toast+后果挽回。
   - 第三阶（10% 精力）：兜底与新手——强制引导最多 3 步、空状态引导、长尾功能"?"按需查阅。
2. **双轨原则（AI 是加速器，不是必需品）**
   - 每条 AI 路径必须有等价的无 AI 路径；两轨汇合到同一个任务草稿对象（QuickTaskDraft）、同一套校验、试跑与保存。
   - 任何含 AI 的改动合入前必须通过"无 AI 冒烟"：关闭 AI 后从入口到保存的整条链路完整可走，手动替代入口显式可见。
3. **黄金标尺**
   - 拿走所有提示后，用户 3 秒内能完成"贴 URL → 下一步"。
   - 不可逆操作（删除任务/字段/清理/覆盖）前必有后果文字 + 确认。
   - 核心任务（贴 URL → 试跑 → 保存）可闭眼完成；冷门入口（YAML/反检测/"?"）睁眼可找。

## 2. 产品形态：任务画布（Task Canvas）

### 2.1 从"步骤"到"区域"

替换五步向导为**单一连续滚动界面**，自上而下五个区域。**区域由输入状态驱动展开，不是固定顺序**：贴了 URL 才出草稿区，有了草稿才出字段区，试跑完才出验证区。用户始终只看到"与当前进度相关"的部分（渐进披露），但每个区域都有永久"展开/收起"入口（高自由度）。

```
┌──────────────────────────────────────────────────────────┐
│ 任务画布                                   [简单|专业|开发者] │
├──────────────────────────────────────────────────────────┤
│ ① 意图区（常驻）                                           │
│    [ 贴 URL 或一句话描述任务……            ][开始]          │
├──────────────────────────────────────────────────────────┤
│ ② 草稿区（生成后展开）— 计划卡片                           │
│   来源徽标：AI 推荐(0.95) / 模板 XX / 手动                 │
│   访问范围 │ 采集方式 │ 附件与PDF │ 变化监测 │ 输出 │ 预算   │
│                          [先试跑 3 页]  [查看 YAML]       │
├──────────────────────────────────────────────────────────┤
│ ③ 字段区（展开后展开）— 复核式表格                         │
│   字段 | 选择器 | 示例值 | 状态     [视觉点选|智能提取|手动] │
├──────────────────────────────────────────────────────────┤
│ ④ 验证区（试跑后展开）— 内联试跑结果                       │
│   样例抓取 ✓ 字段命中 8/9 ✗1  → 一键回字段区修正            │
├──────────────────────────────────────────────────────────┤
│ ⑤ 交付与运行区（保存后展开）                                │
│   输出格式 | 存储 | 调度/监测     [▶ 运行]  进度  [查看结果] │
└──────────────────────────────────────────────────────────┘
```

### 2.2 核心机制：草稿即主界面

QuickTaskDraft 从"中间产物"升级为"主界面状态"。任何区域的修改 → 更新同一草稿 → 触发对应区域重验证。AI 只影响"草稿怎么来"，不影响"草稿长什么样、怎么验、怎么跑"。

#### 2.2.1 并发写入：版本号乐观锁 + 按域脏标记（应对 AI 后台回写）

草稿对象同时被 UI 编辑、AI 后台增强（_AIEnrichWorker）、模板推荐、试跑结果四路写入，必须显式定义冲突策略：

- 草稿携带单调递增的 `draft_version`（整体乐观锁，防并发写本身）；所有写入方携带生成时的 `draft_version`，目标版本不匹配即拒绝写入。
- 脏标记**按数据域拆分**，而非全局一档：`field_dirty`（字段区/抓取规则）、`output_dirty`（输出格式/存储）、`schedule_dirty`（调度/监测）、`scope_dirty`（URL/范围/预算）。
- AI/系统回写只受**其对应域**的脏标记约束：例如用户改了输出格式（`output_dirty=true`）**不阻塞** AI 的字段增强；只有 `field_dirty=true` 才把 AI 字段建议挂起为"建议"。
- **「保存草稿」只持久化，不清除任何域脏标记**——脏标记是内存编辑态与 AI 回写冲突的控制器，与是否存盘无关；保存时顺带持久化当前脏标记状态，便于下次加载继续阻断旧 AI 回写。
- 域脏标记只在用户对该域显式"采纳 AI 建议"或"确认修改"后清除；整体 `draft_version` 在"保存草稿 / 保存并运行"时推进（版本号是持久化基线，与脏标记相互独立）。

#### 2.2.2 YAML 单一编辑权（消除双重事实来源）

- 画布草稿（创建期编辑态）与 CrawlConfig（保存后的配置对象）是两个对象；**任一时刻只有一个入口可写**。
- 画布内的"查看 YAML"为只读源码视图（UI → YAML 单向导出）。
- 独立 YAML 编辑器页（专业模式）为可写入口：其修改经既有 `config_changed` / `sync_to_form` 信号链更新 CrawlConfig。
- **画布加载/返回时检测外部变更**：若 YAML 编辑器存在未同步到画布草稿的更改，画布编辑区灰显并弹框「检测到外部 YAML 编辑」，提供「加载 YAML 覆盖草稿」或「放弃 YAML 保留草稿」二选一；绝不允许两入口同时可写且互不同步、静默覆盖。
- **覆盖即清理（防旧建议污染）**：选择「加载 YAML 覆盖草稿」时，在清除脏标记的同时**废弃（Abort）全部挂起的 AI/系统建议队列**（_AIEnrichWorker 未回写结果、模板推荐、字段补全），并 Toast「已加载外部配置，挂起的 AI 建议已清除」。此规则适用于一切"覆盖/重置草稿"操作（加载 YAML、忽略推荐、重置），防止旧配置生成的建议在 dirty 清除后自动回写污染新配置。
- **锁定期间禁保存**：画布处于只读/模态锁定态时，右上角「保存草稿」同步禁用（灰显 + Tooltip「请先完成当前操作」），锁定解除后恢复——避免保存字段尚未回写的中间态草稿。
- **实时冲突检测（画布常驻打开时）**：画布打开期间监听应用内全局信号 `config_externally_updated`（由 YAML 编辑器保存成功时经既有 `config_changed` 信号链发出）。一旦捕获，画布**立即**置只读保护态并弹出同样的二选一对话框，无需等到"加载/返回"。禁止"画布可写 + YAML 已改"并存。

#### 2.2.3 试跑状态与源数据绑定（Provenance）

- 试跑报告携带生成时的**字段指纹** `field_hash`（基于字段名 + 选择器 + 顺序的有序序列化 MD5）。
- 采集范围或字段规则任何增删改/排序 → 立即将验证区「试跑通过」置为「待重新试跑(stale)」，显示警告条"采集范围或字段规则已变更，请重新试跑"；「开始全量运行」按钮随之禁用（Tooltip 说明原因），直至新试跑完成。输出与调度变更只重新校验交付设置，不使采集试跑失效。
- 运行/全量执行前校验 `field_hash` 与当前字段集一致；不一致即拒绝，避免用旧字段集的试跑状态运行新字段集。

### 2.3 与现有入口的关系

- 五步向导 → 被画布取代；保留 YAML 编辑器作为专业模式下的独立"源码编辑"入口（侧栏项，双向编辑），画布内仅提供只读 YAML 视图切换。
- 首页 → 意图区即首页核心输入框（首页 Hero 保留，其余快捷入口收敛进画布/侧栏）。
- 模板市场、场景管理、格式互转、PDF 工作台 → 保持侧栏独立入口，画布在草稿区提供"选用模板/场景"的即用入口。

### 2.4 交互规则：关注焦点（Focus Mode）

- 状态驱动的自动展开**仅限区域首次出现**（如试跑完成首次展开验证区，并高亮 3 秒）；"首次出现"标记绑定**会话生命周期**——重新进入画布即重置，不与永久偏好混淆。
- 普通区域（字段/交付）的折叠偏好持久化到本地配置；自动化（AI 增强、试跑完成）不得强行改变。
- **验证区永不消失**：只允许收起为"底部状态栏"（始终可见，显示最近一次试跑结果摘要与"查看详情"），杜绝"新手收起验证区 → 再次试跑无反馈 → 反复点按钮"的死锁。
- 跨区域联动（如"一键回字段区修正"）只做**滚动定位 + 高亮**，不自动展开。

## 3. 区域详设

### 3.1 意图区（第一阶核心）

- **交互**：单个输入框，支持「贴 URL」「一句话描述」「两者（URL + 描述）」；回车或"开始"进入草稿生成。空白时显示输入示例占位（如"例如：https://example.org 采集新闻标题"），非教程。
- **即时反馈（第二阶）**：
  - 输入停顿 600ms 后探活（可访问性 / robots / 静态或动态 / 分页线索），结果以内联徽标呈现（site_inspector + AsyncFetcher，走 EgressBroker 审计）。
  - "开始"按钮在输入为空/非法时禁用，Tooltip 说明原因（"需要有效网址"）。
- **AI 轨 / 无 AI 轨**：AI 开启 → 后台 AI 增强草稿（_AIEnrichWorker，失败降级）；AI 关闭 → 本地 compile_natural_language 或 draft_quick_task 生成。本地结果始终先展示。
- **AI 开关只影响"下一次生成"**：切换 AI 开关（开/关）**不重置、不重新生成**当前画布已加载的草稿与字段——仅对用户再次在意图区点击「开始」后的新生成生效；来源徽标切换（AI/模板/手动）同理。杜绝"误触开关导致手动工作丢失"。
- **首启引导（第三阶，最克制）**：首次打开画布且无任何历史任务（含草稿与已保存任务）时，意图区输入框短暂高亮 + 气泡提示「试试粘贴一个网址开始」（3 秒自动消失），非弹窗、不阻塞操作；关闭后记录本地偏好不再重复。
- **复用**：home.py 输入逻辑、ux_service、natural_language_task、site_inspector。
- **验收**：拿走提示后 3 秒内能完成"贴 URL → 开始"。

### 3.2 草稿区：计划卡片（第一阶核心）

- **交互**：把 QuickTaskDraft.confirmation() 渲染为分节计划卡片（访问范围/采集方式/附件与PDF/变化监测/输出格式/资源预算）。每节可点击展开微调；每节旁"可修改"标记（源自 editable_sections）。
- **模式感知渲染（跟随简单/专业/开发者）**：简单模式下卡片只展示 3 项核心摘要（网址、采集方式简写、预计页数），其余参数折叠进"高级设置 ▶"默认不展开；专业/开发者模式展示全部分节。避免长尾术语（滚动加载/重试次数等）在简单模式下摊开。
- **试跑页数（资源预算分节，已决策）**：「资源预算」分节提供手动"试跑页数"滑块，默认 3、范围 1-10，专业模式可见、简单模式折叠进"高级设置"；**不随验证区展开自动变化**。上限 10 页防试跑消耗过多流量/触发反爬，与全量运行页数限制分离。
- **来源徽标**（透明度关键）：🤖 AI 推荐（含置信度）/ 📦 模板 XX / 👆 手动——让用户知道"这草稿怎么来的"，可一键切换来源。
- **模板/场景即用（G1）**：贴 URL 后本地推断（B-2 L1/L2）推荐模板，卡片显示"将按 XX 模板配置（置信度 0.95）"；确认闸门（RecommendationConfirmationEngine）前移到此处，保留"手动选择模板/场景"下拉与"忽略推荐"。
- **动作**：主按钮"先试跑 3 页"；次按钮"查看 YAML"（只读源码视图）；"保存草稿"常驻右上角（见 §3.4 两级保存）。保存动作移入验证区后。
- **拒绝理由采集（产品数据闭环）**：在"忽略推荐 / 更换模板"旁提供轻量"👎 不准确"图标，点击记录预设标签（网址不匹配 / 字段太少 / 结构过时）。**必须携带诊断快照**（异步上报、不阻塞主流程）：URL 域名、L1/L2 命中分类、置信度、命中来源（L1/L2/L3）、推荐模板与字段、用户动作标签——写入 observation_store / metrics，作为 SiteCategorizer L3 迭代的真实语料；**无快照的标签视为无效，不入库**。
- **schema 对齐（已决策）**：优先扩展 observation_store 现有用户反馈类记录（payload 增加诊断快照字段 + `feedback_type="template_rejection"`）；若现有 schema 不支持用户反馈类记录，则新建 `template_feedback` 表（字段映射上方诊断快照）；兜底为本地 `logs/template_feedback.jsonl` 暂存、后台批量导入。P2 开发前完成对齐，不阻塞 P0/P1。
- **双轨**：无 AI 时草稿来自模板渲染/默认值/手动表单，卡片结构、审核动作完全一致。
- **复用**：QuickTaskDraft、TemplateCatalog 渲染、SiteCategorizer、RecommendationGate、template_market。
- **验收**：推荐可被忽略且手动路径零障碍；草稿来源始终可见可改。

### 3.3 字段区：复核式表格（第一阶核心）

- **交互**：表格列出字段（名称/选择器/示例值/状态✓✗）。模板已配字段显示"来自模板 XX，可增删"——用户默认只做复核。
- **性能基线（字段 ≥50 为常态）**：字段表格采用 model/view 架构（QAbstractTableModel + QTableView，虚拟滚动内建），默认只展开前 10 条 + 「还有 N 个字段，点击加载」。
- **计时口径（可验收）**："加载 <500ms" 指**数据就绪后**（field list ready 事件触发）到 QTableView 完成首屏绘制的渲染耗时；网络请求、AI 推理、本地启发式计算**不计入**，由骨架屏/加载态覆盖。验收用例：50 字段数据已就绪的基准环境，点击「展开全部」后首屏渲染完成 <500ms。
- **递进式入口（避免决策瘫痪）+ 双轨透明**：默认只显示一个主按钮，但按钮文字**动态显示当前路径**——AI 开启显示「🤖 智能补全字段」，AI 关闭显示「⚙️ 启发式补全字段」。补全完成后字段表顶部以淡灰小字标注「本次由 AI / 启发式生成 · 点击『更多方式』切换」，透明且不干扰。
- **去重追加（Upsert，绝不覆盖用户字段）**：「智能补全」对当前表格做**去重追加**——AI/启发式返回的字段只补充表格中不存在的项，**绝不删除或覆盖**用户已有字段（含手动输入、视觉点选所得）。同名但选择器不同时，保留用户版本，AI 版本以灰字旁注展示供参考。
- **模式可见性**：简单模式下「更多方式」**完全隐藏**（不显示、不置灰，保持极简心智）；若对自动补全结果不满意，右上角提供一键「切换到专业模式」（Toast 提示"切到专业模式可手动调整字段"），切换后「更多方式」出现——能力不隐藏，只是改变可达路径。专业/开发者模式下，「更多方式」折叠展开视觉点选、手动输入两个次级入口。
- **即时反馈（第二阶）**：字段加载骨架屏；应用字段后 Toast + 可撤销；字段删除需确认（后果文字"将移除字段 X 及已抓取数据"）。
- **验收**：无 AI 时主按钮走本地启发式，"更多方式"中视觉点选/手动可用；字段状态即时可见。

### 3.4 验证区：内联试跑（第二阶核心）

- **交互**：点"先试跑 3 页"后，区域内联展示：样例抓取、字段命中率、警告（如"3 个字段未命中"）、单字段示例值。结果卡片给出"一键回字段区修正"入口（滚动定位 + 高亮，见 §2.4）。
- **重复试跑（自动替换 + 可回溯）**：字段变更后再次试跑，自动覆盖验证区旧结果（不弹确认，避免模态干扰）；验证区底部提供「查看上次试跑记录」折叠入口，保留最近 3 次试跑报告的轻量历史，便于字段选择器调试对比。
- **两级保存（不强制卡点）+ 运行唯一出口**：
  - 「保存草稿」常驻右上角：随时可存，不强制试跑，任务状态 `draft_status=pending`（覆盖"先配好晚点跑"、内网不可试跑等场景）。
  - 「保存并试跑/运行」（验证区）：点击后触发试跑；**运行/全量执行前必须通过试跑**——这是项目既有安全护栏（防浪费流量/反爬风险），试跑由"保存的门槛"降为"就绪的门槛"。
  - **运行唯一出口**：交付区不设独立「▶ 运行」按钮（只做输出/存储/调度配置）；底部常驻「开始全量运行」是试跑与交付校验通过后的唯一执行入口，物理消除"绕过试跑"的状态歧义。已就绪任务在运行与历史页运行，不属画布职责。
  - 任务列表区分「草稿(pending)」与「已就绪(ready)」。
- **即时反馈**：试跑进度走统一进度协议（ingest/fetch/extract/export 阶段权重），完成 Toast + "立即运行"入口。
- **复用**：sample、progress.py、Step5 试跑报告渲染。
- **验收**：任意时刻可保存草稿；全量运行前必须试跑通过；试跑结果可一键回到字段区；保存后有明确去向。

### 3.5 交付区（第二阶）

- **交互**：输出格式、存储目标、调度（定时/变更监控）展开项，均有合理默认。**不设独立运行按钮**——执行入口唯一在验证区（§3.4 运行唯一出口），避免绕过"试跑即就绪"护栏。
- **不可逆操作**：删除任务、清理数据、覆盖配置前双重确认 + 后果文字。
- **复用**：Step4 下载选项、scheduling、change_monitor、任务监控页、进度协议。
- **验收**：画布内不存在绕过试跑的执行入口；运行进度与完成跳转由验证区承接。

## 5. 双轨与 AI 降级明细

| AI 功能点 | AI 路径 | 无 AI 等价路径 | 降级时机 |
|---|---|---|---|
| 草稿生成 | 一句话 → AI 解析增强 | 本地 compile / 模板渲染 / 手动表单 | AI 未配置、隐私禁用、超时、越权拦截（_AIEnrichWorker 已覆盖） |
| 模板推荐 | B-2 L1/L2/L3 推荐 | 手动选模板/场景、忽略推荐 | enable_sniffing=false 或未注入 fetcher 时 L3 跳过 |

| 计划审核 | 无 AI（审核动作与 AI 无关） | 同左 | — |

合入门槛（每项 AI 改动）：**无 AI 冒烟**——`mode=disabled` 或断网后，从意图区到保存全链路可走；每个 AI 入口旁有显式手动替代。
**并发约束**：AI/系统回写一律受 §2.2.1 版本号 + 按域脏标记保护，用户手动编辑优先，AI 建议只挂起不覆盖；改外围配置（输出/调度）不阻塞 AI 对核心字段的增强；「保存草稿」不清除脏标记。
**运行约束**：全量运行前必须满足——试跑通过 且 `field_hash` 与当前字段集一致（§2.2.3）。
**埋点约束**：拒绝理由必须携带 §3.2 诊断快照，无快照不入库。

## 7. 验收标准（全局）

1. **双轨等价**：关闭 AI 后，全流程（贴 URL → 草稿 → 字段 → 试跑 → 保存 → 运行）完整可走，且每一 AI 入口旁有显式手动替代。
2. **黄金标尺**：拿走提示 3 秒走通核心路径；不可逆操作有后果文字 + 确认。
3. **功能不降级**：模板、场景、视觉点选、智能提取、试跑、进度、调度、监控、YAML 均在新画布中可达（见 §4 映射表逐项核对）。
4. **三阶自检**：第一阶无教程；第二阶操作必有反馈；第三阶引导不超 3 步。
5. **冲突不覆盖**：用户手动编辑后，任何 AI/系统回写只挂起为"建议"，不自动覆盖草稿；改外围配置不阻塞 AI 字段增强（§2.2.1 冒烟用例）。
6. **折叠偏好受尊重**：自动化不强制改变用户已收起的普通区域状态；验证区永不消失（至少为状态栏），重复试跑始终有可见反馈（§2.4 冒烟用例）。
7. **运行唯一出口**：画布内不存在绕过试跑的执行入口；交付区无运行按钮，试跑通过后才能触发全量运行（§3.4 冒烟用例）。
8. **外部编辑检测**：YAML 外部编辑未同步时画布灰显并提供「加载/放弃」二选一，不存在静默覆盖；画布常驻打开时经 `config_externally_updated` 事件实时触发，不等加载/返回（§2.2.2 冒烟用例）。
9. **双轨透明**：字段补全按钮与结果标注显示实际路径（AI/启发式），专业用户可判断与切换（§3.3）。
10. **试跑失效**：字段变更后试跑状态立即 stale，运行按钮禁用直至重新试跑；运行前 `field_hash` 一致校验（§2.2.3 冒烟用例）。
11. **模式感知卡片**：简单模式卡片仅核心 3 项，长尾折叠进"高级设置"（§3.2）。
12. **字段性能**：50 字段时滚动 ≥30fps；"加载 <500ms"按数据就绪→首屏绘制计时，网络/AI 不计入（§3.3）。
13. **覆盖即清理**：加载 YAML 覆盖后挂起的 AI/系统建议队列被废弃，不污染新配置（§2.2.2 冒烟用例）。
14. **试跑可回溯**：字段变更后再次试跑自动替换，保留最近 3 次试跑历史可对比（§3.4）。
15. **锁定禁保存**：画布锁定态「保存草稿」禁用，不保存中间态草稿（§2.2.2）。
16. **简单模式隐藏更多方式**：完全隐藏 + 一键切专业模式恢复，能力可达（§3.3）。
17. **去重追加**：智能补全不删除/覆盖用户已有字段，仅去重追加；同名异选择器保留用户版 + AI 灰字旁注（§3.3 冒烟用例）。
18. **开关不重置**：AI 开关/来源切换不影响当前已加载草稿，仅作用于下一次"开始"生成（§3.1 冒烟用例）。

## 8. 风险与开放问题

- **画布 vs QWizard 存量**：Step1-5 组件迁移量较大；P0 先迁移行为再清理旧页，YAML 视图与闸门逻辑保留复用。
- **信息密度**：字段多时画布过长——用区域级折叠 + 默认只展两个区域缓解；若仍过长，字段区可切表格密集视图。
- **推荐置信度过低**：L1/L2 未命中且 L3 关闭时，草稿退化为 generic 模板 + 手动路径，不阻塞。
