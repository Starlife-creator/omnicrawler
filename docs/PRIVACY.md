# 隐私政策与数据留存说明（终端用户）

> 适用版本：1.0.1 · 配置协议：v5 · 维护状态：现行

本文面向使用 OmniCrawler 桌面客户端与单机源码安装版的**终端用户**，说明本软件在本地
保存哪些数据、保存在哪里、留存多久、卸载时如何清理，以及哪些合规责任由部署方承担。
技术安全模型与网络边界见 [安全与合规](SECURITY_AND_COMPLIANCE.md)；漏洞报告渠道见
根目录 [SECURITY.md](../SECURITY.md)。

## 1. 核心承诺

- **无遥测上传**：本软件不内置 Sentry、PostHog、Mixpanel、埋点 SDK 或任何第三方
  分析服务；不把您的配置、任务数据、浏览记录、日志或环境信息外发到开发方服务器。
- **无崩溃上报上传**：当前版本**没有**崩溃报告上报通道；异常现场只留在本地日志中。
  设置面板里的「崩溃上报」开关是预留占位项，在上报链路落地之前不产生任何外发报文
  （见本文第 5 节「设置开关现状」）。
- **本地优先**：除您在配置中显式指定的目标站点、API 与外部存储（S3、PostgreSQL、
  OpenSearch、Redis 等）外，一切任务数据都存放在您本机的工作目录内。
- **日志脱敏**：写入日志与诊断包的 URL 会自动脱敏域名以外的查询参数；内嵌凭据的
  URL（`scheme://user:pass@host`）在记录前被遮蔽。

## 2. 本地数据清单

下表按数据类别列出来源、默认位置与留存口径。便携版（PyInstaller 打包）的数据根随
`PORTABLE.flag` 落在应用目录；源码版与安装版落在可移植数据根（`portable_data_root()`，
可由工作区搬迁流程或自定义数据模式改写，见 [桌面运行时](DESKTOP_RUNTIME_1.4.md)）。

| 类别 | 用途 | 默认位置（相对数据根） | 留存口径 |
|---|---|---|---|
| 状态库 `state.sqlite3` | 任务、运行记录、队列、复核状态与断点恢复依据 | 数据根 / 工作区配置指定路径 | 随工作区长期保留；卸载不自动删除，需手动清理 |
| 本地原始副本（raw） | 已捕获页面 / 附件的本地副本，供回归与复核 | 工作区 `data/`、`work/` 目录 | 按配置与保留策略清理；手动删除前建议备份 |
| 运行日志 | 任务执行记录、错误堆栈、超时与重试 | `logs/omnicrawler.log`（5 MB × 3 份轮转） | 轮转覆盖，旧日志被新日志顶出；按运行分文件与事件索引的演进见 [运维手册](OPERATIONS.md) |
| 模型 / 组件缓存 | OCR 模型、第三方组件下载缓存 | `.omnicrawler/cache/`（含 paddlex / paddle / HuggingFace / ModelScope 子目录） | 可安全整目录删除，下次运行按需重建 |
| 指标快照 | 进程内计数器与延迟直方图落盘 | `metrics.json`、`metrics.prom`（工作区输出目录） | 仅本机观测用途，不外发；随输出目录清理 |
| 会话 / Cookie | 浏览器会话保持 | **默认不持久化**；确需续跑须配置具名 session 并限制在工作目录内 | 退出运行后由会话配置决定是否保留 |
| 凭据 / Cookie / Token | 站点登录凭据、API 密钥 | 仅经环境变量（`OMNICRAW_*`）或系统 keyring 提供；配置文件中以 `secret://<key>` 引用，**不明文落盘** | 跟随系统密钥环生命周期；配置文件不保存明文值 |
| AI / 提取缓存 | 字段推荐与候选结果的进程内缓存 | 默认**仅内存**，不写磁盘 | 进程结束即释放；显式开启 `cache_entries` 后上限 1024 项、8 MiB |
| 导出交付物 | CSV / JSONL / Excel / PDF 等结果文件 | `output/` 目录（可在配置中改写） | 由用户自行保管与删除 |

## 3. 采集对象与个人信息

- 本软件只访问您在任务配置中显式声明的目标站点、API、文件或本地数据源；不扫描
  本机其它目录、不收集通讯录、浏览器密码或磁盘文件清单。
- 采集结果中若包含公开网页上出现的个人信息（姓名、邮箱、电话等），这些数据作为
  任务产物保存在您本机；是否留存、对外提供或删除，由任务发起者负责判断与处置。
- 网络访问受出口策略约束：本机、私网、链路本地与保留地址默认拒绝；robots.txt
  默认遵守；详见 [安全与合规](SECURITY_AND_COMPLIANCE.md)「网络安全模型」一节。

## 4. 卸载与清理

### 便携版（ZIP / tar.xz / dmg）

1. 退出工作台与所有后台任务；
2. 删除应用解压目录（程序本体随之移除）；
3. 位于应用目录内的 `.omnicrawler/`、`logs/`、`data/`、`work/`、`output/` 与
   `runtime/models/` 随目录一起删除；若您把数据模式改为自定义路径，需到该路径
   另行手动清理；
4. 系统 keyring 中已保存的站点凭据需在系统凭据管理器中单独删除。

### 源码安装版

1. 删除项目目录与虚拟环境（`.venv`）；
2. 按上节数据清单清理自定义工作区、日志、模型缓存与输出目录；
3. 环境变量中配置的 `OMNICRAW_*` 密钥在您的 shell 配置或系统环境变量中移除；
4. 系统 keyring 凭据单独删除。

> 卸载程序**不会**自动删除任务数据、原始副本与导出产物——这些可能是您需要留存的
> 成果；清理前请自行备份需要保留的部分。

## 5. 设置开关现状

- **隐私脱敏开关**（`privacy/redact_enabled`，默认开启）：控制日志与错误对话框中的
  URL / 凭据参数脱敏；关闭后日志可能记录带查询参数的完整 URL，请谨慎操作。
- **崩溃上报开关**（`privacy/crash_report`，默认关闭）：当前版本**未接入任何上报
  通道**，开关仅持久化到本地设置；上线上报链路（本地崩溃队列，不上传或经显式
  同意后上报）之前，打开开关不会产生外发行为。

## 6. 部署方义务（服务端 / 自托管场景）

当您把 OmniCrawler 部署为团队服务、接入外部存储或采集含个人信息的公开页面时，
以下事项**不属于桌面客户端内置承诺**，由部署方在其组织的法律框架内自行完成与留痕：

- 个人信息最小化、处理依据、告知与跨境传输合规；
- 留存期限、访问控制、导出与删除请求的响应流程；
- 员工账号、Cookie、Token 的轮换与访问审计；
- 数据源的服务条款、robots、API 速率与版权合规判断。

以上责任边界与 [安全与合规](SECURITY_AND_COMPLIANCE.md)「合规决策由部署方完成」
一节保持一致；模板 `license` 字段仅为提示，不替代法律审查。

## 7. 变更记录

漏洞请按 [SECURITY.md](../SECURITY.md) 的私有渠道报告，勿在公开 Issue 中披露细节。
