# 市场生态与分发协议

OmniCrawler 当前不依赖账号服务器或市场 API。市场是独立 Git 仓库和可镜像的静态目录；
插件与模板首先是用户拥有的文件夹，作者可自主选择私下分享或投稿市场。

## 核心状态

| 状态 | 包含内容 | 信任含义 | 谁能推进 |
|---|---|---|---|
| 制作中 | 源文件和说明 | 未形成可验证分发物 | 作者 |
| 创作者签名包 | 规范 manifest、完整载荷哈希、创作者签名和公开身份 | 可验证来自某把作者密钥，可 P2P 分享 | 作者 |
| 市场投稿态 | 同一创作者包 + `submission.json`，位于 `submissions/` | 等待审核，不可作为市场包安装 | 作者提交 PR |
| 市场发布态 | 原创作者字节 + 维护者对同一 manifest 的复签 + market overlay | 市场审核过固定字节 | 维护者冷签 |
| 已撤销 | 已签 catalog 中的撤销/墓碑记录 | 禁止新安装或运行受影响版本 | 维护者 |

不存在“先上传才得到可分享包”的中间依赖。完成并签名就是可私下分享的状态，上传是可选动作。

## 一份 manifest，两份签名

`package.manifest.json` 是规范 JSON，包含包类型、ID、版本、创作者指纹和精确载荷文件哈希。
作者与维护者都签署它的原始字节：

```text
payload files ──SHA-256──> package.manifest.json
                              ├── creator signature
                              └── maintainer signature
```

市场不得重写作者签名覆盖的文件。展示名、市场 handle、审核时间等市场字段放在独立
`market.yaml` overlay；因此市场可以管理展示和状态，却不能悄悄改变作者作品。

## 无服务器身份

- 全局归属标识是公钥指纹；用户名只是作者请求的显示名。
- 本地注册允许重名，不尝试做无法兑现的全局唯一验证。
- 首次市场发布时才分配唯一 `market_handle`：首位 `alice` 保留原名，后续不同指纹依次使用
  `alice-01`、`alice-02`。
- 指纹到 handle 的映射稳定；同一密钥发布新包或更新时不会换名。
- 包 ID 已发布后只允许原作者指纹更新，维护者无权改写或转移归属。

## 投稿安全边界

外部 PR 只能修改 `submissions/`。CI 静态验证规范 JSON、签名、哈希、精确文件集合、路径、
插件 AST 元数据、模板 safe YAML、域名、凭据泄漏和 DCO。投稿代码不会被 import 或执行。

需要动态测试时，由维护者把已核对哈希的包放入一次性隔离环境：无个人凭据、默认断网或最小
域名、受限文件系统、测试结束销毁。动态测试结果不能替代签名和静态门禁。

## 客户端安装

市场浏览和安装前必须：

1. 下载 `catalog.json` 与 `catalog.json.sig`；
2. 用内置市场公钥验证原始目录字节；
3. 与按市场源隔离的本地缓存比较，拒绝 sequence/时间回退；
4. 解析条目并下载 manifest 声明的每个文件；
5. 验证创作者签名、维护者签名、目录中的 manifest 哈希、包 ID/版本和精确文件集合；
6. 使用 staging 目录，验证成功后再原子替换安装目录。

P2P 导入不要求维护者签名，但在落盘前显示来源、指纹、权限和域名，并要求用户明确确认。
默认只建立当前插件范围的信任，不扩大成作者级永久信任。

## 版本更新

- 版本必须符合 SemVer 并严格递增；
- 更新签名密钥必须等于现有包归属指纹；
- 新版放在 `versions/<version>/`，旧版作者签名字节不覆盖；
- catalog overlay 只在审核和复签成功后指向新版；
- 同版本覆盖、降级和另一把密钥接管一律拒绝。

## 插件与模板同步

两类包共用身份、manifest、双签、P2P、投稿、catalog 和更新制度。差异只在静态审核：

- 插件检查 `PLUGIN_METADATA`、执行模式、权限、依赖、域名和许可；
- 模板检查 YAML 结构、ID/版本、固定 seed 与域名、`secret://` 引用以及数据来源条款。

未来若增加分块模板，应复用同一 package type 扩展和签名协议，而不是建立旁路市场。

## 镜像与未来服务器

静态镜像只复制 catalog、包和签名，不重签，信任等级保持不变。若未来贡献量、撤销时效或统计
需求证明需要服务器，服务器只应承担索引、审核排队和通知；包身份和离线验签仍由本协议决定，
不能把安全退化成“服务器说用户名是谁就是谁”。
