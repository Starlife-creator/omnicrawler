# 市场生态与分发协议

> 适用版本：0.15.0 · 配置协议：v5 · 维护状态：现行（历史状态见归档；功能验证以验收账本为准）

OmniCrawler 当前不依赖账号服务器或市场 API。市场是独立 Git 仓库和可镜像的静态目录；
插件与模板首先是用户拥有的文件夹，作者可自主选择私下分享或投稿市场。

## 核心状态

| 状态 | 包含内容 | 信任含义 | 谁能推进 |
|---|---|---|---|
| 制作中 | 源文件和说明 | 未形成可验证分发物 | 作者 |
| 创作者签名包 | 规范 manifest、完整载荷哈希、创作者签名和公开身份 | 可验证来自某把作者密钥，可 P2P 分享 | 作者 |
| 市场投稿态 | 同一创作者包 + `submission.json`，位于 `submissions/` | 等待审核，不可作为市场包安装 | 作者提交 PR |
| 市场发布态 | 原创作者字节 + 维护者对同一 manifest 的复签 + market overlay | 市场审核过固定字节 | 维护者冷签 |
| 已撤销 | 已签 catalog 中的撤销/墓碑记录 | 禁止新安装或运行受影响版本 | 维护者 |

不存在“先上传才得到可分享包”的中间依赖。完成并签名就是可私下分享的状态，上传是可选动作。

## 一份 manifest，两份签名

`package.manifest.json` 是规范 JSON，包含包类型、ID、版本、创作者指纹和精确载荷文件哈希。
作者与维护者都签署它的原始字节：

```text
payload files ──SHA-256──> package.manifest.json
                              ├── creator signature
                              └── maintainer signature
```

市场不得重写作者签名覆盖的文件。展示名、市场 handle、审核时间等市场字段放在独立
`market.yaml` overlay；因此市场可以管理展示和状态，却不能悄悄改变作者作品。

## 无服务器身份

- 全局归属标识是公钥指纹；用户名只是作者请求的显示名。
- 本地注册允许重名，不尝试做无法兑现的全局唯一验证。
- 首次市场发布时才分配唯一 `market_handle`：首位 `alice` 保留原名，后续不同指纹依次使用
  `alice-01`、`alice-02`。
- 指纹到 handle 的映射稳定；同一密钥发布新包或更新时不会换名。
- 包 ID 已发布后只允许原作者指纹更新，维护者无权改写或转移归属。

## 投稿安全边界

外部 PR 只能修改 `submissions/`。CI 静态验证规范 JSON、签名、哈希、精确文件集合、路径、
插件 AST 元数据、模板 safe YAML、域名、凭据泄漏和 DCO。投稿代码不会被 import 或执行。

需要动态测试时，由维护者把已核对哈希的包放入一次性隔离环境：无个人凭据、默认断网或最小
域名、受限文件系统、测试结束销毁。动态测试结果不能替代签名和静态门禁。

## 客户端安装

市场浏览和安装前必须：

1. 下载 `catalog.json` 与 `catalog.json.sig`；
2. 用内置市场公钥验证原始目录字节；
3. 与按市场源隔离的本地缓存比较，拒绝 sequence/时间回退；
4. 解析条目并下载 manifest 声明的每个文件；
5. 验证创作者签名、维护者签名、目录中的 manifest 哈希、包 ID/版本和精确文件集合；
6. 使用 staging 目录，验证成功后再原子替换安装目录。

P2P 导入不要求维护者签名，但在落盘前显示来源、指纹、权限和域名，并要求用户明确确认。
默认只建立当前插件范围的信任，不扩大成作者级永久信任。

## 依赖提示（打开即检测）

插件把第三方依赖声明在 `PLUGIN_METADATA["dependencies"]`。宿主在两处给出**只读**提示，
不会在打开界面时自动安装或弹框打断：

- **插件市场页**：已安装插件若声明依赖缺失，列表行显示 `[缺依赖 N]` 只读徽标，
  悬浮列出缺失项；依赖齐全时静默（不打扰）；
- **设置 → 环境与依赖**：展示原生依赖 / 能力组件的就绪徽标，缺失项给出**就地安装**按钮
  （用户主动点击才动作，绝不自动装）。

依赖缺失的严重度是 **warning 而非 error**：manifest 声明的是插件依赖全集，本次配置未必
全部用到（实测某些插件的浏览器依赖只在特定采集层级才需要）。一律判 error 会把「能跑通的
运行」挡在门外，反而教会用户忽略预检。安装同样走统一的多源回退安装器（官方源优先），
配置与镜像加速见 `CONFIG_REFERENCE.md`「依赖安装与镜像加速」。

## 版本更新

- 版本必须符合 SemVer 并严格递增；
- 更新签名密钥必须等于现有包归属指纹；
- 新版放在 `versions/<version>/`，旧版作者签名字节不覆盖；
- catalog overlay 只在审核和复签成功后指向新版；
- 同版本覆盖、降级和另一把密钥接管一律拒绝。

## 插件与模板同步

两类包共用身份、manifest、双签、P2P、投稿、catalog 和更新制度。差异只在静态审核：

- 插件检查 `PLUGIN_METADATA`、执行模式、权限、依赖、域名和许可；
- 模板检查 YAML 结构、ID/版本、固定 seed 与域名、`secret://` 引用以及数据来源条款。

未来若增加分块模板，应复用同一 package type 扩展和签名协议，而不是建立旁路市场。

## 多索引（federated catalogs，#77 Phase 1）

默认仍是**一条官方策展源**（未配置时由 `plugins.catalog_url` 派生，行为与升级前完全一致）。
此外可以同时启用多个索引：

```yaml
plugins:
  catalogs:
    - url: https://raw.githubusercontent.com/<你>/<你的索引>/main   # 索引基址
      kind: community        # curated | community | topic
      priority: 10           # 同一个 id 出现在多个索引时，小的先展示（缺省 100）
      trust: <PEM 文本 / 文件路径 / base64 / hex:>   # 留空＝官方内置信任根
      enabled: true
```

每个源**各自独立验签**：`trust` 留空即用官方内置信任根；**信任根为空 ⇒ 该源判失败**
（不"不验签就用"）。**取数或验签失败的源照样出现在报告里并带原因**，不会静默消失 ——
否则用户会以为"市场里就这么多"。

### 信任信号三级（**别把它们当成同一种东西**）

| 徽标 | 含义 | **它不保证什么** |
|---|---|---|
| **官方策展** | 索引由官方维护，条目经人工审核 + 维护者签名 | —— |
| **社区索引** | 由社区/第三方维护的索引；条目**未经官方审核** | 不代表官方认可、不代表质量或安全 |
| **P2P 未审核** | 创作者签名包直装（无索引背书） | 完全依赖创作者身份与你自己判断 |

★ 三级都**保留创作者签名校验**（安装永远要过创作者签名 + 清单固化的 sha256），
差别只在"谁为可发现性背书"，不在"包是否被验签"。UI/CLI 的徽标就是为了**不让人误以为
所有源都经过官方审核**。

### 同一 id 出现在多个索引

唯一键是 `(id, creator_fingerprint)`：

- 同 id **同指纹**多处出现 ⇒ 按 `priority` 择一展示，但把**全部来源**记在条目上；
- 同 id **不同指纹** ⇒ 双方都标 `conflict`，**不静默择一**（防换密钥接管同名 id）；
- 展示用 `市场/<id>`，便于区分同名。

## 自建索引（最小模板）

想让自己仓库里的插件被装上，只需要两个文件（放进任意可被 HTTP 读取的目录，
或直接用本地目录 / 镜像）：

```
你的索引仓库/
├── catalog.json          # 见下
└── catalog.json.sig      # 用**你的**索引密钥对 catalog.json 的**原始字节**做 ed25519 签名
```

```json
{
  "schema_version": 1,
  "plugins": [
    {
      "id": "your_plugin",
      "name": "your_plugin",
      "version": "1.0.0",
      "publisher": "your-name",
      "plugin_file": "plugin.py",
      "signature_file": "plugin.py.sig",
      "signature_algorithm": "ed25519",
      "source_base": "https://your-host/path/to/your-package-repo"
    }
  ]
}
```

- **`plugin.py` 与 `plugin.py.sig` 不需要放进索引仓库**：用 `source_base` 指向
  **你自己的仓库/发布地址**即可。索引只**背书**、不搬运字节，创作者签名原样保留
  （即"聚合而非搬运"）。`source_base` 缺省时用索引基址（单仓模式，和以前一样）。
- 跟索引给的地址去取包**不会削弱安全**：包仍要用**创作者签名**验、仍要对清单固化的
  sha256、目标主机仍要过出口策略。索引能决定"去哪儿取"，**决定不了"取到的东西算不算数"**。
- 用户添加你的索引：GUI「市场 → 管理源…」，或配置 `plugins.catalogs`（见上），
  或 CLI `omnicrawler plugins catalogs add <url>`。

## 离线与受限网络

- **每个源的离线快照分别保存**（按源 URL 派生缓存路径），一个源不可达不影响其他源；
- **DNS 逐地址尝试（AAAA 无路由时回退 IPv4）**，避免"域名解析成功但整条下载超时"；
- **支持显式代理**（配置里的 `http.proxy`），且重定向仍过策略与审计；
- 官方索引的**离线快照随包分发**（`plugins.bundled_catalog_dir`），断网时官方条目仍可见。

## 镜像与未来服务器

静态镜像只复制 catalog、包和签名，不重签，信任等级保持不变。若未来贡献量、撤销时效或统计
需求证明需要服务器，服务器只应承担索引、审核排队和通知；包身份和离线验签仍由本协议决定，
不能把安全退化成“服务器说用户名是谁就是谁”。
