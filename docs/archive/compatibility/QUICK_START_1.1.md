# OmniCrawler 1.1：按任务操作指南

## 先判断入口 URL 怎么填

入口 URL 首先填写浏览器地址栏中能看到、并且你有权访问的栏目页、搜索页或详情页。

| 看到的情况 | 入口怎么填 | 接下来选择 |
|---|---|---|
| 点击下一页后地址栏出现 `page=2` | 填第一页栏目地址 | 自动识别；必要时在专业模式填写页码参数 |
| 地址栏不变，但列表内容变化 | 仍填地址栏中的栏目入口 | "需要登录、搜索、点击或滚动"→"学习点击/搜索/翻页" |
| 页面空白，稍后才出现数据 | 填地址栏入口 | 动态浏览器；让系统观察 XHR/fetch |
| F12 的 Network 中有返回 JSON 的请求 | 初学者仍填页面入口并使用操作学习 | 专业用户可审核生成的 REST 配置 |
| 有明确 RSS、Sitemap 或公开 API 文档 | 填真实订阅/API 地址 | RSS/Feed、Sitemap 或 REST |

不要把 F12 中的脚本、图片、`document` 请求或临时签名地址当成 API。正确候选通常是 XHR/fetch、
响应为 JSON、翻页后重复出现，且列表条目数量与页面接近。OmniCrawler 会显示请求方法、样本数量、
稳定字段、分页证据和是否需要小样本复核。

## 场景：某栏目下某主题的所有 PDF

1. 第一步把任务命名为"栏目—主题—PDF"，目标选择"采集某栏目/主题的附件并处理 PDF"。
2. 填浏览器地址栏中的栏目入口，不必先找到 PDF 直链。
3. 如果搜索或翻页时网址不变，点"学习点击/搜索/翻页"：在可见浏览器中输入主题、点击搜索，
   再点击一次下一页或滚动到底；完成后关闭该窗口。
4. 第四步"主题词"填写任一命中词；"必含词"用于同时必须出现的词；"排除词"用于排除失效、
   征求意见稿等。保留"不确定候选"可避免只根据链接文字漏掉正文中才出现主题的文件。
5. 启用附件下载和 PDF 处理。OCR 选择"自动"：有文本层就直接提取，扫描件才使用 OCR。
6. 若以后要检查原网址是否换了文件，启用"网址不变也重新访问并保存变化版本"。
7. 先试跑 3 页，核对访问范围、保留/排除理由、文件类型和抽取字段，再执行全量任务。

文件扩展名只用于早期发现。最终还会检查 `Content-Type`、`Content-Disposition` 和文件签名，
因此 `/download?id=123` 这类没有 `.pdf` 的地址也可以保存为 PDF。

## 动态站点的学习结果

操作学习记录点击、填写、按键和滚动；密码输入会写成 `secret://browser_password`，不会明文保存。
运行这些动作时，浏览器会观察后台接口并在工作区生成：

- `output/api_discovery/*.json`：接口、样本、字段、置信度与验证状态；
- `output/api_discovery/*.yaml`：可执行 REST 计划，包含 GET/POST、脱敏请求头、请求体、
  `item_path` 和已识别分页；
- `raw/browser_api/*.json`：受大小限制的原始接口证据。

先保留浏览器方案完成试跑。只有生成接口被样本验证后，才建议切换到 REST；登录态、验证码、
一次性 token 或 WebSocket 驱动的站点可能仍需浏览器。工具不会绕过访问控制或验证码。

## 同一 URL 内容变化

"同址变化"不是重新生成 URL，而是让已完成网址在下一轮重新进入待抓取状态。HTTP 页面会发送
`If-None-Match`/`If-Modified-Since`；服务器返回 304 时复用上一版本，不重复解析。返回新内容时保存：

- 原始内容哈希版本；
- 结构化记录语义版本；
- 字段级新增、删除和修改；
- 运行间对比与质量报告。

动态页面则比较浏览器渲染结果和捕获到的 API 响应。建议定时任务连续两轮确认"删除"，避免短暂
网络失败被误报为内容删除。

## AI 可以怎么选

AI 默认关闭。可选本地模型、云端 OpenAI 兼容 API 或自定义兼容服务；同一配置可按能力路由到不同
Provider。API 地址应包含服务的 `/v1` 基础路径，模型填写服务实际模型 ID，密钥使用
`secret://env/变量名` 或系统凭据存储引用。

AI 适合模板解释、字段语义、模糊主题判断和文档增强。网络边界、robots、下载、哈希去重、条件请求、
版本比较和审计均由确定性内核处理；AI 不可用时这些核心能力仍可运行。

## 问号帮助与模式

每个非显然选项旁的 `?` 点击后显示用途、填写方式、示例和限制。简单模式隐藏并发、手写分页、资源档、
选择器细节和 YAML；专业模式开放这些字段；开发者模式再开放插件与诊断。模式切换只改变显示，不会
删除配置。模板应用前必须查看差异，默认组合到现有任务，不覆盖任务名称、入口、主题、字段和输出。
