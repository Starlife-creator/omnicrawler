## 第一批：组件注册表与可信安装

不同组件安装、卸载和回滚使用同一跨进程事务锁，避免共享清单提交相互覆盖。安装对同一份私有暂存包字节验签和解压，阻止源包在两步之间变化。名称、版本和路径在写入前校验；清单损坏明确失败。

版本字节保留，升级与卸载保存完整旧清单；回滚重新验哈希并恢复元数据。记录路径使用组件根目录下相对路径，完整目录搬迁后可恢复。提交持久标记可在下次访问时重放。CLI 从独立受信公钥文件读取信任根，缺失时默认拒绝签名安装。

验证：组件多进程提交、升级/卸载回滚、目录搬迁、非法标识、提交重放、损坏清单和正常 CLI 签名入口通过；现有工作区组件回归通过。移除 CLI 信任接线后新回归明确失败，源文件按字节恢复，随后正向通过。static 全部门禁通过，无跳过。

## 第三批：参数声明与安全渲染

TemplateCatalog.render 统一检查声明的 `type`、`required`、`minimum`、`maximum`、`enum`。支持 string/integer/number/boolean/array/object；仅声明类型的参数会将 CLI 文本按整数或 JSON 转换，整值替换保留数据类型。布尔值不能充当整数；非有限数、越界和枚举类型错配拒绝。`strict=False` 允许待补必填项，已给出的值仍须满足约束。错误只展示参数名，不复述参数内容。模板健康检查同时验证默认值。

页码模板为终止页声明 1–1000 的整数范围。CLI 先在目标目录校验临时配置，成功后原子替换；`--force` 只授权覆盖。覆盖前通过现有 ConfigHistory 保存可恢复快照；失败清除临时文件并保留原任务。

验证：参数类型、范围、草案、枚举、默认值、旧模板回归及成功/失败覆盖路径通过。反向验证及门禁证据为 `.tmp/parameters-negative.log` 和 `.tmp/parameters-static.json`。验收摘要、参数复用面板和冻结 GUI 场景不属于本批已完成项。

## 第六批：会话资源互斥与缓存失效

工作区会话锁由任务资源、登录窗口、文件桥接和恢复隔离共用；仍有活动任务时编辑立即明确失败。Pipeline 构造失败释放锁，关闭时先等在途工作结束，再关闭客户端/状态并释放锁。复用通用 OS 文件锁实现组件注册表锁，不引入额外进程服务。

新任务及会话编辑清除工作区 HTTP 缓存；被清除的旧 jar 清空且禁止再落盘，避免隔离后的文件被旧引用重建。get_cookie_session 缓存命中时不再构造并解密一个随后丢弃的实例。恢复隔离动作须持有会话锁，不能与任务并行修改登录态。

验证：任务阻止会话替换、隔离后旧引用不能复写、新任务可重新获得锁、关闭等待先于客户端回收，以及既有 Pipeline/登录/桥接/组件并发路径通过。恢复不等待在途的关闭方式后生命周期回归失败，按字节还原。证据为 `.tmp/session-lifecycle-negative.log` 与 `.tmp/session-lifecycle-static.json`。GUI 等待停止后重登录与按认证指纹重试继续在后续批次接入。

## 第七批：明确认证失败与精确重试

新增可选 `source.auth_check`，由站点模板或用户明确声明 `status_codes`（401/403）、`selector`（登录表单 CSS）与 `redirect_paths`（精确登录路径）。多条件同时满足才判认证失败；未声明时普通 401/403 保持原行为。失败元数据只保存原因码和账号/代理/目标域的身份摘要。

StateStore 仅重入队明确给出的认证失败指纹，同时核对失败状态、原因码、会话摘要和登录代次。相同登录快照只可重试一次，不触碰已完成、策略拦截、网络错误或其他账号的失败。RecoveryCenter 核对当前工作区、快照账号/代理和 Cookie 域覆盖，再按摘要选择重试；下一次执行使用 resume 并重建资源。

示例：`source.auth_check: {status_codes: [403], selector: 'form.login'}`。声明须来自实际站点观察；请勿将所有 403 解释为登录过期。默认空声明不改变既有任务。

验证：明确诊断、多条件、普通状态码、身份过滤、登录代次、Cookie 域覆盖、错账号快照，以及生产 Pipeline 跨运行持久化与 resume 路径通过。取消认证重试的作用域筛选后回归失败并字节还原；证据 `.tmp/auth-recovery-negative.log` 与 `.tmp/auth-recovery-static.json`。GUI 停止/登录/恢复按钮接入仍待下一批。

## 第八批：停止、重登录与恢复接线

登录页先请求停止任务，轮询至旧 Worker 进程退出后再打开登录窗口。等待可取消，工作区切换取消待执行动作，关闭页面幂等回收登录窗口和计时器。停止确认不能代替进程退出确认。用户选择恢复时，先成功同步本次 Cookie，再重入队匹配的认证失败请求并以 resume 启动 Worker；普通启动与旧会话元数据仍默认为新执行。

删除快照与清除本任务本地登录态分开呈现。后者在会话锁内将当前账号快照、HTTP Cookie 及浏览器 Profile 移入工作区恢复目录，移动失败恢复原位置，其他账号保留。HTTP 持久化失败明确报告同步失败，防止使用旧会话继续任务。

验证：Worker 退出确认、恢复意图传递、旧元数据兼容、本地注销隔离与失败还原、认证提示以及现有会话回归通过。取消 Worker resume 接线后回归失败并字节还原，证据 `.tmp/worker-resume-negative.log` 与 `.tmp/worker-login-static.json`。Qt 等待、取消、切换工作区、幂等关闭和禁止无同步恢复回归已加入现有 CI 测试集合；遵守 AGENTS.md，本地未执行 GUI 矩阵，不宣称 CI 或实机通过。
