# OmniCrawler 2.8.0 第一性原理优化方案

> 状态：已实施首批高风险、低歧义改进；外部用户研究、签名和跨机器验收仍需外部证据。

## 用户的最小成功闭环

用户需要的不是“能填很多配置”的工具，而是：描述目标、知道系统将做什么、补齐真正必要的信息、低风险试跑、拿到可追溯结果，并能在失败或中断后恢复。

| 约束 | 2.8.0 决策 | 后果与保护 |
|---|---|---|
| 用户一开始不知道字段名 | 首页以自然语言任务描述为主，生成可编辑草案 | 草案绝不自动扩大范围或绕过确认；仍显示来源、范围、输出与预算 |
| 中途被必填校验打断 | 所有会阻止试跑的信息前置到第一页 | 高级设置不再阻断首次成功路径，专业/开发者能力仍保留 |
| 通知和页面状态失真 | 通知自动关闭有独立计时器兜底，转场析构停止动画 | 防止事件循环、动画回调或对象销毁顺序异常导致界面残留 |
| 关闭窗口时任务仍运行 | 先请求取消，再等待 QThread 停止 | 牺牲极小的关闭等待，换取不访问已销毁控件和不损坏状态 |
| 离线发布不可复现 | 使用版本化的离线构建目录，复用本地依赖/浏览器/运行时缓存 | 不覆盖保留发行物；仍执行清单、SBOM、冒烟和 ZIP 校验 |

## 不应退让的系统不变量

- 任务网络请求必须通过 EgressBroker；robots、范围、预算、凭据与审计始终有效。
- AppConfig、配置 v5、SQLite WAL 状态、原始证据和可恢复语义保持兼容。
- 自然语言只能帮助配置，不能替代用户确认；高风险或不确定的推断必须标明。
- GUI 异步对象均有取消、关闭和析构路径；用户离开页面不应留下悬挂回调。

## 后续验证

1. 用至少 5 个新用户任务验证：从描述到首次试跑的时间、第一页完成率、误配置率和主动放弃率。
2. 在不同 DPI、主题、屏幕阅读器和低性能设备上验证首页可达性与线程关闭体验。
3. 在签名、托管 CI 和真实用户数据授权环境中验证发布链，且不将本机验证结论外推为外部认证。
