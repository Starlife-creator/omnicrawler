# OmniCrawler 0.13.1 发布报告

> 发布日期：2026-09-20；配置协议：v5；公共 API：兼容。

## 发布结论

0.13.1 是一次**收口版本**：把 v0.13.0（2026-09-17）之后积压的三批工作一次交付。

| 批次 | 主题 | 一句话 |
|---|---|---|
| **R1–R5** | 走查暴露项 | 让产品"说真话"：提示指向真因、做不到的明说、状态变更 URL 默认拒绝 |
| **B1–B5** | 品牌融入 | 窗口/托盘/产物图标与两仓 README logo；跨仓一致性由断言看住 |
| **I1 / I2** | 分发形态 | Linux 用户级安装（应用菜单条目）；Windows 首启快捷方式（默认不勾） |

任务模型、工作区格式、导出格式**均未变化**；配置协议仍为 v5，公共 API 兼容。
**有两处交付值变更**，见「交付值变更」一节 —— 升级前请确认。

## 已交付改进

### 一、走查暴露项 R1–R5（12 项，2026-09-18 闭环）

- **R1（R1.1–R1.4）交付层说实话**：提示与状态不再掩盖真实原因；**状态变更 URL 默认拒绝**
  （爬取过程中地址栏语义变化时不再默默继续）。
- **R2（R2.1–R2.3）提示指向真因**：错误/提示信息指向实际原因，而不是就近的表象。
- **R3.1 不再无条件开浏览器**：auto-analyze 先走轻量路径，需要时才用浏览器；
  保留 `--always-browser` 作为逃生阀（行为可预测、可回退）。
- **R3.2 交互信号有归宿**：识别到的交互信号要么变成动作，要么变成**明确告警** ——
  不再"看见了但什么也没发生"。
- **R3.3 / R4.1 需求语义有承载**：无法满足的需求会**明说**，并**同批撤回过时的"做不到"声明**。
- **R3.4 / R3.5 字段命名与恒定列**：字段名纳入**祖先类名**以避免歧义；
  恒定值的列不再被当成噪声删掉。
- **R3.6 类名里写值的元素**：能枚举、能取值、能映射（此前这类元素取不到值）。
- **R4.2 JSON 记录路径改候选打分**：单对象响应不再取错记录。
- **R4.3 地址类字段归一为绝对 URL**（**只补全、不改写**已有绝对地址）。
- **R4.4 AI 的 `config_patch`**：要么真的接上、要么如实说明没接上（不再静默丢弃）。
- **R5.1 `transform` 排序与分组聚合** 落地，并撤回过时的能力声明。
- **R5.2 分页信号落成契约形状**；iframe 场景给出定位信息。

### 二、品牌融入 B1–B5

- **B1 运行时图标**：窗口与托盘 `setIcon`、`app.setDesktopFileName("omnicrawler")`
  （Wayland 下应用图标匹配的前提）、9 个运行时资产落位 —— **源码运行即可见**。
- **B2 二进制图标**：4 个 spec 的 `icon=` 接线；并加**构建产物图标守卫**
  （在真产物上断言 Windows PE 的 `RT_GROUP_ICON`、macOS 的 `.icns` 与 `CFBundleIconFile`）。
- **B3 主仓门面**：41 个品牌资产落位、README 出现 logo、许可登记、入口指引收口。
- **B4 市场仓门面**：8 个门面资产 + README logo（市场仓**只减不增**，不接收运行时图标）。
- **B5 跨仓一致性**：主仓断言两仓品牌文件**逐字节相同**、清单双向覆盖、禁止资产缺席；
  「主仓改了、市场仓忘了」这类漂移从此有人看管，而不是靠"记得一起改"。
- 相关：便携包**不带**门面资产（门面资产只在仓库里），运行时资产随包。

### 三、分发形态 I1 / I2

- **I1 Linux 用户级安装**（不需要 root）：包内 `installer/install-user.sh` 把应用树
  搬进 `~/.local/opt/OmniCrawler`，按**最终绝对路径**生成 `.desktop`、装 7 尺寸 hicolor
  图标、把 CLI 软链进 `~/.local/bin`。
  ★ 刻意不做"就地注册"：`Exec=` 若指向解压目录，用户清理下载目录后即失效并留死链。
  **卸载保护用户数据**：默认只摘条目/图标/软链；检测到便携数据根在应用目录内时
  `--remove-prefix` **拒绝**，须显式 `--purge-data`。前置依赖**只检测、不自动装**
  （自动安装需要 root）。**不做** `deb`/`rpm`/AppImage（系统域 + "卸载即清目录"对数据根是灾难）。
- **I2 Windows 首启快捷方式**：首启的**既有**欢迎弹窗多一个"在桌面创建快捷方式"复选框，
  **默认不勾**；设置菜单另有显式重复入口；非 Windows 上控件不出现。
  实现是**纯 ctypes**（`IShellLinkW` + `IPersistFile`），**零新运行时依赖**。
  正确性靠 **CI 读回断言**（写入后用系统 API 读回 target / working directory / icon 逐字段比对，
  并核对 `.lnk` 头魔数），"文件存在"不算通过。

### 判据修复（"哑掉"、"静默降级"与"只在别的平台上才说话"的判据）

- **便携产物文件名的 edition 一致性检查在 Linux 上从未生效**：正则只认 `zip|tar.gz|dmg`，
  而 Linux 产物是 `.tar.xz` ⇒ 永不命中。补 `tar\.xz` 后该检查才真的说话。
- **Linux 安装前缀的路径归一化会静默降级**：传盘符路径时被当成相对路径，解析落空后
  前缀退化成 `/前缀名`，把整棵应用树写到意料之外的位置。改为：接受盘符绝对路径、
  解析为空或父目录为根时**显式报错**。
- 安装脚本的**就地重跑**与文档/方案不符（应"跳过复制、幂等"而非报错退出），已修正；
  并堵住"就地 + `--move` 会把刚装好的树删掉"这一语义反转。
- **两条只在 macOS 上暴露的 `bash 3.2` 兼容缺陷**（本机 bash 5 与 Linux 都复现不了）：
  ① 数据根检测用 `A && B` 作循环体最后一条命令 ⇒ 最后一个条件为假时 `set -e` **静默终止**
  （"拒绝删树"看似正确，其实根本没走到拒绝那一步）；② `$VAR` 紧跟全角标点 ⇒ 3.2 把多字节字符
  **吞进变量名**（有 `set -u` 崩溃、无 `set -u` 静默丢值）。两条都改为显式写法，
  并把规则**前移到构建期**（`tools/check_linux_delivery.py` 现在会挡住这类写法）。
- **mypy 的分析平台与 CI 不一致**：`ctypes.WinDLL` 只在 Windows 的 typeshed 里存在，
  本地（Windows）判绿、CI（ubuntu）判红。已在 `[tool.mypy]` 钉 `platform = "linux"`，
  并让平台专属 API 一律走 `getattr(ctypes, "X", None)`。
- **平台专属模块不得拖垮 Linux 覆盖率门禁**：Windows-only 的 COM 管道从"平台判定"后面
  收进单一函数并声明不可覆盖（其正确性由 windows-latest 的读回断言保证），
  上层编排改为**任何平台可测**（本地模拟 Linux 实测 27% → 89%）。

## 验证与交付

- **本地可复现**：`python tools/self_verify.py --set static` **16/16**；
  受影响套件（`tests/unit/{tools,core,gui}`、`tests/gui/`）全绿；品牌跨仓断言真跑通过。
- **行尾契约按真实检出验证**：交付的 `.sh` / `.desktop` 必须纯 LF —— 用 `git checkout-index`
  真落盘再数 CR，并做反向断言（摘掉作用域规则后 `.desktop` 立刻变 CRLF）。
  CRLF 的交付件在用户侧会直接报 `/usr/bin/env: 'bash\r': No such file or directory`，
  而构建机上看不出来。
- **交给 CI 判定的部分**（本地无 Linux 环境，明确说明）：三平台便携构建、
  `portable-smoke` 在**全新 runner** 上解压**已上传归档**后复跑、
  **Linux 归档级安装冒烟**（解压真产物 → 跑安装 → 断言 `Exec=` 绝对且目标真实存在、
  7 张图标齐、`desktop-file-validate` 通过或**可见跳过**）、B2 真产物图标守卫。
- 交付物：源码包 / wheel / 各平台便携包（Standard + Full）+ 各自完整的版本化暂存目录；
  完整性以 `SHA256SUMS-<版本>.txt` 为准，SBOM / provenance 一并交付。

## 交付值变更（升级前请确认）

- **地址类字段归一为绝对 URL**（R4.3）：相对地址会被补全为基于最终 URL 的绝对地址。
  **只补全、不改写**已经是绝对的地址；若下游依赖"原样相对地址"，请在配置中确认。
- **字段命名与列集合可能变化**（R3.4 / R3.5）：字段名现在可能带**祖先类名**以避免歧义；
  恒定值的列不再被当作噪声删除。**导出的列名/列数可能与 0.13.0 不同**。
- **状态变更 URL 默认拒绝**（R1）：抓取过程中地址栏语义变化时默认不再继续；
  依赖"跟随变化"的既有任务可能需要显式放行。

## 升级与回滚

- 从 0.13.0 直接覆盖升级即可；配置与工作区格式无变化（除上述交付值变更）。
- Linux 想用应用菜单入口：解压后执行 `./installer/install-user.sh`（可选，不装也能用）。
- Windows 想建快捷方式：首启勾选，或从「设置」菜单点「创建桌面快捷方式」。
- 回滚：装回 0.13.0 即可。已创建的快捷方式 / 桌面条目可用同包内的
  `installer/uninstall-user.sh` 单独摘除，不影响回滚。

## 未覆盖

- **桌面/开始菜单快捷方式"双击之后"的表现**（冷启动、杀软首扫、图标显示）只能在实机上
  人工确认，归入人工走查项；本版本只保证 `.lnk` 写入字段正确。
- Linux 安装脚本的**图形环境差异**（KDE / XFCE 等对 hicolor 与 `.desktop` 的处理）未逐一验证；
  已按 freedesktop 规范实现，并保留 `desktop-file-validate` 作为语法判据。
- **不做**"自动固定到任务栏 / 开始屏"的任何承诺（无受支持 API，唯一变通要重启用户的
  explorer，属静默改用户环境）。

## 合规与诚实条款（固定字段，B14-💭-3）

- **不绕过**：本版本遵守 robots.txt、只采已获授权站点，不绕过验证码、付费墙、
  访问控制或站点安全策略；隐身/undetected 能力仅用于已授权站点并经 EgressBroker 统一出口。

- 本版本的每项结论都附**可复现命令或提交号**；无法在本地验证的部分（真实便携产物内
