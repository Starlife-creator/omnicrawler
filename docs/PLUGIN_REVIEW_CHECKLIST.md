# 插件市场人工审核清单

本文档用于市场 `reviewed` 质量档的人工审核。自动化和 AI 可以提供证据与风险提示，
但不能代替审核员作出结论，也不能自动修改权限、豁免或发布状态。

## 审核顺序

1. CI 静态门禁通过；
2. 审核员固定并核对 `package.manifest.json` 的完整 SHA-256；
3. 按本清单人工复核；
4. 必要时在一次性隔离环境进行动态测试；
5. 审核员记录结论；
6. 维护者对同一份 manifest 原始字节复签；
7. 生成市场 overlay 和已签名 catalog。

外部投稿代码不得在普通 CI 中 import 或执行。动态测试不能代替静态检查、创作者签名或
维护者复签。

## 1. 包完整性和作者归属

- [ ] `package.manifest.json` 是规范 JSON，文件集合精确且所有 SHA-256 匹配；
- [ ] `package.manifest.creator.sig` 能由 `creator.identity` 中的公钥验证；
- [ ] manifest 中的创作者指纹与公开身份一致；
- [ ] 新版本由现有包的同一创作者指纹签名；
- [ ] 包 ID 未被另一把密钥占用；
- [ ] 版本符合 SemVer 且严格高于已发布版本；
- [ ] 投稿没有修改正式目录、作者记录、catalog 或维护者签名。

## 2. 契约和核心逻辑

- [ ] 使用契约 2：顶层 `handle(operation, payload) -> dict`；
- [ ] `PLUGIN_METADATA` 是可由 AST 静态读取的 `dict` 字面量；
- [ ] 插件不导入 `omnicrawler`，宿主能力只经 `omnicrawler_sdk` 请求；
- [ ] 每个 operation 正确分派，所有结果都是可 JSON 序列化的对象；
- [ ] 无 `eval`、`exec`、任意子进程、`os.system` 或其他绕过能力代理的危险行为；
- [ ] 实际行为与 `listing.md` 描述一致，没有隐藏功能；
- [ ] 异常、超时、空结果和 fallback 行为清楚且可预测。

## 3. 最小能力面

- [ ] 代码实际使用的能力不超过 `permissions`；
- [ ] 网络访问声明 `network:scoped` 和精确、必要的 `domains`；
- [ ] 文件访问声明 `files:read` 和精确、必要的 `input_files`；
- [ ] `dependencies` 与实际 import 双向一致；
- [ ] 默认使用 `subprocess`；如申请 `in_process`，已说明不可替代性、风险和到期时间；
- [ ] 权限相较上一版本没有未说明的扩大；
- [ ] 配额、响应大小、分页终止和重试策略有明确上限。

## 4. 数据、网络和凭据

- [ ] 读取 records 后是否还会发起网络请求，已明确说明数据去向；
- [ ] 网络目标与插件功能直接相关，没有宽泛、动态或无关域名；
- [ ] 优先使用宿主 auth 注入，避免插件获取明文密钥；
- [ ] 如必须使用 `secrets.get`，manifest 白名单、理由和审计行为完整；
- [ ] 日志、错误、证据和导出内容不包含 Token、Cookie、私钥或个人凭据；
- [ ] `listing.md` 说明第三方服务条款、频率限制、数据许可和用户责任。

## 5. 依赖、许可和可维护性

- [ ] 插件许可证使用市场允许的 SPDX 标识；
- [ ] 第三方依赖许可证兼容且已准确声明；
- [ ] 没有来源不明的复制代码、素材或二进制文件；
- [ ] 变更记录、版本号和实际内容一致；
- [ ] 包含本地 fixture 测试，默认测试不依赖公网或真实凭据；
- [ ] `plugins audit --local .` 与 `pytest -m plugin_contract` 均通过。

## 6. 动态测试（需要时）

- [ ] 测试对象的 manifest 哈希与人工复核对象完全一致；
- [ ] 使用一次性环境、无个人凭据、受限文件系统和默认断网或最小域名；
- [ ] 测试结束后销毁环境，不把测试信任扩展到作者或未来版本；
- [ ] 动态结果作为审核证据保存，但不自动触发 Pass/Fail。

## 7. 发布签名和目录

- [ ] 维护者复签的是已人工核对的同一份 `package.manifest.json` 原始字节；
- [ ] `package.manifest.maintainer.sig` 有效，冷私钥未进入 CI、仓库或普通工作机；
- [ ] `market.yaml` 只包含市场字段，没有改写创作者载荷；
- [ ] `gates_evidence` 与人工结论、manifest 哈希和时间一致；
- [ ] catalog 条目指向正确版本，`catalog.json.sig` 有效且 sequence 单调递增；
- [ ] 撤销记录、同版本覆盖、降级和换密钥接管检查均通过。

## AI 辅助审核的界面限制

- AI 区只能展示证据、疑点和建议检查项；
- AI 区不得提供审核通过、拒绝、签名或豁免按钮；
- 人工签字和维护者签名操作必须与 AI 分析区明确分离；
- AI 输出不得自动改变权限、审核状态、发布状态或信任列表。
